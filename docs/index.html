YicesTRA

A solver for real arithmetic with transcendental functions

GitHub Example Usage Installation Paper People Contribute

YicesTRA is a tool to decide the satisfiability of quantifier-free formulas of non-linear real arithmetic extended with transcendental functions. The current version supports the sine function sin, the exponential function exp, and the constant pi. The tool is an extension of the Yices 2 SMT solver. The source code is available here under the GPLv3 license.

YicesTRA operates in two modes:

  • default mode: Checks for an exact solution and returns sat or unsat.
  • δ-satisfiability mode (option --mcsat-delta): Allows a user-specified tolerance (δ). It stops and reports delta-sat if a solution satisfies the formula within that δ margin (see below).

Examples

Consider the following formula, which asks for a real number in the interval [0, π/2] whose sine has a square larger than 1/2 and whose exponential is smaller than 3:

∃x ∈ [0, π/2].   sin(x)2 > 1/2  ∧  exp(x) < 3

Encoding the formula

YicesTRA reads the SMT-LIB 2 format. The formula above is encoded as follows (intro.smt2): 

(set-logic QF_TRA)
(declare-fun x () Real)
(assert (<= 0 x))
(assert (<= x (* (/ 1 2) pi)))
(assert (> (* (sin x) (sin x)) (/ 1 2)))
(assert (< (exp x) 3))
(check-sat)
(get-model)

The logic QF_TRA tells the solver that the formula belongs to transcendental real arithmetic. Within this logic the symbols sin, exp and pi are predefined and must not be declared. Everything else is standard SMT-LIB 2.

Solving the formula

We run the solver on the file:

$ ytra intro.smt2
    sat
    ((define-fun x () Real 1.0))

The solver returns sat and gives a model (x = 1) because the input contains (get-model). This is a valid solution since sin(1)2 ≈ 0.708 > 0.5 and exp(1) ≈ 2.718 < 3.

An unsatisfiable formula

Running the solver on exp(x) < 1 + x returns unsat (exp-tangent.smt2): 

(set-logic QF_TRA)
(declare-fun x () Real)
(assert (< (exp x) (+ 1 x)))
(check-sat)

$ ytra exp-tangent.smt2
    unsat

An unsat response means the formula has no real solution (in this case, because the exponential function lies above its tangents).

A δ-satisfiable formula

The equation sin(x) = 1/2 has one solution in [0, 2]: x = π/6. Because π/6 is transcendental and YicesTRA currently only computes algebraic numbers, it cannot return sat or unsat. Without options, the solver keeps refining its approximation of π/6 indefinitely (sin-half.smt2): 

(set-logic QF_TRA)
(declare-fun x () Real)
(assert (<= 0 x))
(assert (<= x 2))
(assert (= (sin x) (/ 1 2)))
(check-sat)
(get-model)

To get an answer, set a tolerance with the option --mcsat-delta=D, where D is a positive integer that sets δ = 2−D and enables the delta-sat response. Taking D = 10 yields δ ≈ 10−3: 

$ ytra --mcsat-delta=10 sin-half.smt2
    delta-sat (with delta 10)
    ((define-fun x () Real (/ 36844988291815 70368744177664)))

The returned value x ≈ 0.5235987755983018 differs from π/6 by less than 3·10−15.

Formally (see Gao, Avigad, and Clarke, 2012), a delta-sat answer means the assignment satisfies the δ-weakening of the formula, obtained by relaxing every atom involving a transcendental function by δ (for instance, sin(x) = 1/2 becomes |sin(x) − 1/2| ≤ δ). Note that YicesTRA does not internally relax formulas and will never return delta-sat on formulas that do not feature transcendental functions.

Usage

Input format

  • Header. The file must start with (set-logic QF_TRA), which predefines pi : Real and the functions sin : Real → Real and exp : Real → Real. Do not declare them.
  • SMT-LIB 2 constructs. Supports standard real arithmetic constructs: variable declarations (declare-fun, declare-const for Real and Bool), operations (+, -, *, /), comparisons (<, <=, >, >=, =), Boolean connectives, ite, let, and commands (assert, check-sat, get-model). Rational constants can be written as decimals or fractions (0.5 or (/ 1 2)).

Command line

$ ytra [options] file.smt2
OptionMeaning
--mcsat-delta=D Fixes the tolerance to δ = 2−D, for a positive integer D, and enables the answer delta-sat. Larger values of D make the answer more precise. Without this option the solver only answers sat or unsat.
--dump-models Prints a model after every sat or delta-sat answer, without a (get-model) command in the input file.
--mcsat-help Lists options of the MCSAT engine.
--help Lists further options inherited from Yices 2.

Installation

YicesTRA requires:

  • gperf and GMP, as for Yices 2;
  • libpoly and CUDD (configured with --enable-shared), as for the MCSAT engine of Yices 2;
  • FLINT, version 3 or later (it includes the Arb module), and MPFR.

Once the dependencies are installed, build the tool with:

$ git clone https://github.com/arith-lab/yices-tra.git
$ cd yices-tra
$ autoconf
$ ./configure
$ make

The binary is placed in build/<platform>-release/bin/ytra (for instance build/x86_64-pc-linux-gnu-release/bin/ytra on Linux). If configure does not find a library, pass its location with CPPFLAGS and LDFLAGS. The README on GitHub contains further troubleshooting notes.

How it works

YicesTRA implements an extension of the procedure described in the paper MCSAT Modulo Transcendental Arithmetics. The procedure works within MCSAT, the model-constructing satisfiability calculus of Yices 2, and is built around a new theory plugin, the TRA plugin, that acts as an intermediary between the core MCSAT solver and the existing plugin for non-linear real arithmetic (NRA).

Non-total functions

Unlike the version described in the paper, YicesTRA supports non-total functions; currently just division (/), which is undefined when dividing by zero.

Under SMT-LIB semantics, (/ t1 t2) acts as an uninterpreted function when t2 = 0. Determining whether a transcendental expression equals zero is notoriously hard (dependent on Schanuel's conjecture). YicesTRA therefore uses a δ-relaxed semantics: if it cannot determine whether t2 = 0 at a precision tied to δ, it treats t2 as potentially zero and lets (/ t1 t2) take any value. If a solution relies on this relaxation, YicesTRA reports delta-sat (when --mcsat-delta is set) or continues searching. Crucially, sat and unsat answers still strictly respect SMT-LIB semantics.
